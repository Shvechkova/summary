
## Краткое содержание

Глава 11 посвящена **конвейерной архитектуре** — стилю, при котором данные последовательно проходят через серию обрабатывающих компонентов (фильтров), как на сборочной линии.  Архитектура конвейерного стиля характеризуется разбиением по техническому принципу, поскольку логика приложения разбивается по типам фильтров (производитель, тестер, преобразователь и потребитель). К тому же конвейерная архитектура обычно реализуется в виде монолитного модуля развертывания, поэтому в ней всегда только один архитектурный квант.

---

## 🏗️ Что такое конвейерная архитектура?

![Конвейерная архитектура](../../assets/2025-10-26_19-43-52.png)
Каналы и фильтры взаимодействуют определенным образом, при этом каналы формируют одностороннюю связь между фильтрами, обычно работающую по принципу «точка — точка» (point-to-point)

**Конвейерная архитектура** — это стиль, при котором:
- Данные проходят через **последовательность обрабатывающих компонентов**.
- Каждый компонент (**фильтр**) выполняет свою задачу и передаёт результат дальше.
- Связь между компонентами осуществляется через **каналы**.

> 💬 *"Конвейерная архитектура — это стиль каналов и фильтров, знакомый по Unix-командам (например, `ls \| grep`)."*

---

## 🔧 Основные элементы

### 1. **Фильтры (Filters)**
Обрабатывают данные и передают результат дальше.    Каждый фильтр должен выполнять только одну задачу. Составные задачи должны решаться последовательностью фильтров, а не одним.
Типы фильтров:

| Тип                                | Описание                                                                                                                                                                                                                                     |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Производитель (producer)**       | Начальная точка процесса, являющаяся исключительно исходной точкой, иногда называемой источником.<br>                                                                                                                                        |
| **Преобразователь  (Transformer)** | Принимает входные данные, может выполнять преобразование некоторых или всех данных, после чего пересылает их в исходящий канал. Сторонники функциональной парадигмы усмотрят в этой функции отображение<br>                                  |
| Тестер (tester)                    | Принимает входные данные, тестирует по одному или нескольким критери- ям, после чего может, если нужно, выдать на основе теста выходные данные. Программисты, работающие на функциональных языках, могут заметить, что это похоже на свертку |
| **Потребитель (consumer))**        | Конечная точка конвейера. Иногда потребители сохраняют конечный результат или данные, полученные при прогоне по конвейеру, в базе дан- ных либо показывают конечный результат на экране пользовательского интерфейса.                        |


> 💬 *"Фильтры должны быть простыми, независимыми и легко заменяемыми."*

### 2. **Каналы (Channels)**
Передают данные между фильтрами.
- Могут быть **синхронными** (прямая передача) или **асинхронными** (через очередь).
- Обеспечивают **слабую связанность** между фильтрами.

> ⚠️ Каналы **не должны** быть двунаправленными — данные движутся только вперёд.

## 🔄 Топология

- **Линейная цепочка**: данные проходят через фильтры последовательно.
- **Разветвлённая**: после одного фильтра данные идут в несколько направлений.
- **Циклическая** — редка, может привести к бесконечной обработке.

> 📌 Пример:  
> `Чтение файла → Парсинг → Валидация → Обогащение → Сохранение в БД`

## 🧩 Примеры использования

1. **Обработка данных (ETL)**
   - Извлечение, трансформация, загрузка данных.
   - Пример: логи → парсинг → агрегация → витрина данных.

2. **CI/CD пайплайны**
   - Сборка → тестирование → развёртывание → мониторинг.

3. **Обработка медиа**
   - Видео → кодирование → сжатие → доставка.

4. **Системы потоковой обработки**
   - Kafka Streams, Apache Flink, AWS Lambda.

## 🛠️ Практические рекомендации

### 1. **Сделайте фильтры Stateless**
- Избегайте хранения состояния внутри фильтра.
- Это упрощает масштабирование и отказоустойчивость.

### 2. **Используйте буферизацию в каналах**
- Асинхронные каналы (очереди) сглаживают всплески нагрузки.
- Пример: RabbitMQ, Kafka.

### 3. **Добавьте мониторинг и логирование**
- Каждый фильтр должен логировать вход/выход.
- Метрики: задержка, количество обработанных сообщений, ошибки.

### 4. **Обеспечьте обработку ошибок**
- Стратегии:
  - Повтор (retry)
  - Перемещение в "мёртвую очередь" (dead-letter queue)
  - Компенсирующие действия
